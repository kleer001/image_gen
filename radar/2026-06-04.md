# Model Radar — 2026-06-04
Window: since 2026-06-03. GPU ceiling: 24 GB (RTX 3090; 6.3 GB free at sweep time — ComfyUI/Flux loaded).

Focused sweep: **best open-weights option for photoreal multi-view / camera-angle control** (front / 3-4 / profile / back of a *real-photo* character), since base Flux Kontext resists large viewpoint rotation — especially from a tight real-photo headshot (its documented worst case).

## Image base models
- **Qwen-Image-Edit-2509** (20B MMDiT image-editing model, Apache-2.0) — the editing sibling of Qwen-Image; documents **novel-view synthesis** as a core capability and holds identity/materials/lighting coherent across viewpoint changes (the thing Flux Kontext won't do on real photos). This is a **new base family** for this stack (Qwen, alongside Flux) — cannot co-load with Flux on 24 GB. Fits 24 GB: **quantized** — GGUF **Q6_K ≈ 16.8 GB** (recommended), Q8_0 ≈ 21.8 GB (tight), or fp8 (~16 GB). Source: https://huggingface.co/QuantStack/Qwen-Image-Edit-2509-GGUF (official base: https://huggingface.co/Qwen/Qwen-Image-Edit-2509). Verdict: **try** — this is the direct answer to the photoreal-turnaround gap.
- *(Qwen-Image-2.0 base — still watch-only; open weights not released, carried over from 2026-06-03.)*

## Camera-angle / multi-view control (the actionable piece)
- **Qwen-Image-Edit Multiple-Angles LoRA** — purpose-built for camera control: a 96-pose system over horizontal rotation (0-360°: 0=front, 90=right, 180=back, 270=left), vertical tilt (-30°…90°), and zoom; identity stays coherent across angles. Two versions exist — **match the LoRA to the base**:
  - `qwen-image-edit-2511-multiple-angles-lora.safetensors` (**295 MB**, newest, Jan 2026) — https://huggingface.co/fal/Qwen-Image-Edit-2511-Multiple-Angles-LoRA
  - `Qwen-Image-Edit-2509-Multiple-Angles-LoRA.safetensors` (for the 2509 GGUF base above) — https://huggingface.co/MonsterMMORPG/Wan_GGUF
  - ⚠️ **Confirm before download:** the 2511 LoRA targets a 2511 base; pair it with the matching base, or use the **2509** LoRA with the 2509 GGUF transformer to stay consistent. Verdict: **try** (with the 2509 LoRA to match the readily-quantized 2509 GGUF).
- **Flux Kontext Character Turnaround Sheet LoRA** (reverentelusarca, Civitai) — generates front/3-4/profile/back on one canvas, **but tuned for full-body *stylized/illustrated* characters, not real-photo headshots** → wrong fit for this photoreal subject. Source: https://www.runcomfy.com/comfyui-workflows/flux-kontext-character-turnaround-sheet-lora. Verdict: **skip** for this use case.

## ComfyUI nodes / tools
- **jtydhr88/ComfyUI-qwenmultiangle** — interactive Three.js viewport (3D handles / sliders / presets) that emits the prompt strings the Multiple-Angles LoRA expects. Turns "rotate to profile" into a precise pose instead of prompt-wrestling. Source: https://github.com/jtydhr88/ComfyUI-qwenmultiangle.
- **city96/ComfyUI-GGUF** — required to load the Qwen GGUF transformer (already known/on prior radar). Source: https://github.com/city96/ComfyUI-GGUF.

## Bottom line
For photoreal multi-view of a real-photo character, the answer is **Qwen-Image-Edit-2509 (GGUF Q6_K, ~16.8 GB) + the Multiple-Angles LoRA + ComfyUI-qwenmultiangle** — purpose-built novel-view/camera control that base Flux Kontext structurally can't do. It adds a *second* image base family (Qwen) that won't co-load with Flux on 24 GB. The Flux Kontext turnaround LoRA is the wrong tool here (stylized full-body only). One thing to confirm before pulling: match the Multiple-Angles LoRA version (2509 vs 2511) to the chosen base.
