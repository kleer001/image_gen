UPDATE — pipeline update-sweep runbook

An instruction document for a Claude Code instance, not for a human reader. If you are that instance: read this page top to bottom, then execute the sweep.

What this is. A repeatable procedure to keep this local image/video stack at the state of the art. You will (1) digest the current state of the repo, then (2) sweep the open-weights landscape for breakthroughs — in models, LoRAs, and workflows — that improve what this repo already does, and (3) write a dated digest under radar/.
Report only. This sweep never downloads, installs, starts imggen, or edits models.yaml / INDEX.md. Its single output is a markdown digest in radar/. Acting on the digest (cataloging, downloading) is a separate, human-approved step.

Hardware ceiling

Target GPU: 24 GB VRAM (RTX 3090). A model/workflow only counts as installable if it fits in 24 GB, including via quantization (GGUF / fp8). Flag anything that fits only quantized and note the quality/speed cost. If nvidia-smi is available, detect the real VRAM and use that instead of the written ceiling. This is a sovereign/local rig: judge "state of the art" only among open-weights models runnable locally — never closed APIs (Midjourney, Sora, Veo, Kling), which are out of scope by design.

Step 1 Digest the current repo state

Read the tracked catalog files to learn what is already installed, which base families are in use, and what the stack can currently do:

FileWhat to extract
INDEX.mdAuthoritative on-disk inventory — installed model/LoRA filenames (your exclusion set), base families, trigger words, LoRA weights.
models.yamlMachine catalog — every known model's base:, section:, source, date. Anything here is "already known," not new.
models/MODELS.mdHuman notes on style families and search patterns.
workflows/*.jsonThe 26 installed workflows = the capabilities the stack performs today (txt2img, Kontext edit, ControlNet, storyboard, i2v/t2v, upscale, …).
newest radar/*.mdPrior digest — its date is your "since" boundary (see Step 2); its open follow-ups (watch verdicts) are re-check candidates.
TODO.md, ROADMAP.mdKnown gaps and wanted capabilities — weight the sweep toward things that fill these.
Local or remote. Digest state from the tracked files above, not from the models/ directory — it is gitignored and absent in remote/web sessions. Do not ls models/ to decide what is installed; trust INDEX.md + models.yaml.

From this, derive: (a) the set of installed filenames, (b) the base families in use (derive from INDEX.md — do not assume a fixed list), and (c) the current capability/workflow set.

Step 2 Establish the window

The newest dated digest in radar/ sets the "since" boundary — report only what is new since then. If radar/ has no dated digests, or this is an explicit first/catch-up run, use the last 14 days. Record the window and the detected GPU ceiling in the digest header.

Step 3 Sweep the categories

Run several focused web searches per category. The Workflows row is the addition that makes this broader than a pure model sweep — actively look for new SOTA pipelines, not just weights.

CategoryWhat to look forPrimary sources / where to search
Image base models New or updated open-weights foundations & notable checkpoints that beat or upgrade an installed image model. HuggingFace model cards & trending; CivitAI checkpoints; official release notes.
Video models New/updated open-weights video generators (T2V, I2V, S2V, FLF2V, long-shot) within the VRAM envelope of the installed WAN / Hunyuan path. HuggingFace; project GitHubs (Wan, Hunyuan, LTX, FramePack); release notes.
LoRAs (for installed families) Notable new LoRAs for the base families found in Step 1 (Flux.1-dev, Illustrious/SDXL, SD1.5, WAN). Capture trigger + recommended weight. CivitAI (filter by base model); HuggingFace; author pages.
Workflows (ComfyUI & elsewhere) new New SOTA pipelines for what the repo does or wants (txt2img, Kontext/in-context edit, ControlNet, storyboard/identity-lock, i2v/t2v, upscale + frame-interp). Prefer API-format ComfyUI graphs; note node dependencies and whether they fit 24 GB. ComfyUI example_workflows / docs; CivitAI (Workflows filter); OpenArt workflow gallery; comfyworkflows.com; relevant GitHub repos & node READMEs.
ComfyUI nodes / tools Significant new custom nodes, quantization tooling, or pipeline helpers relevant to the installed models (and to unblocking ROADMAP.md items). ComfyUI Registry; GitHub (kijai, XLabs, Kosinkadink, etc.); release notes.

Step 4 Filter, rank, verify

  • Filter: drop anything already installed (Step 1 exclusion set) or already in models.yaml; drop anything that cannot fit 24 GB even quantized.
  • Rank by relevance: does it fill a known gap (TODO.md / ROADMAP.md), upgrade an installed model, or unlock a new capability? Demote incremental point releases.
  • Verify skeptically: prefer primary sources (HuggingFace / CivitAI model cards, GitHub release notes). Many "best of" lists are vendor or SEO blogs — mark any claim resting only on a vendor blog as unverified.
  • Cite a source URL for every entry.

Step 5 Write the digest

Write to radar/<YYYY-MM-DD>.md using today's date, then print a summary of at most 5 lines. Assign each entry a verdict — skip (not a fit), watch (promising but not actionable yet, e.g. weights unreleased), or try (worth considering for install). If a category turns up nothing, say so explicitly rather than padding.

Guardrails

  • Report only. Never download, never edit INDEX.md / models.yaml, never start the stack.
  • Open weights, locally runnable, fits 24 GB — anything else is out of scope.
  • Cite a source URL for every entry; flag vendor-blog-only claims as unverified.
  • Keep it scannable — a handful of high-signal entries beats an exhaustive dump.

Cadence

Run roughly weekly. Two mechanisms keep this on schedule:

  • Session reminder (primary). A SessionStart hook runs scripts/check_sweep_due.py, which prints a "sweep due" nudge whenever the newest radar/ digest is > 7 days old. Works locally and in remote/web sessions.
  • Unattended cron (optional). scripts/update_sweep.sh drives a headless claude -p run of this very page. Install on the rig as, e.g.: 
    0 9 * * 1  /path/to/image_gen/scripts/update_sweep.sh   # Mondays 09:00

This procedure is also exposed as the /model-radar skill (.claude/skills/model-radar/SKILL.md), which defers to this page as the source of truth. Invoking /model-radar and "follow UPDATE.html" are equivalent.
